# Incident AI Assistant

AI 기반 운영 장애 보고서 자동 요약 API

## 1. 프로젝트 소개

Incident AI Assistant는 운영 장애 내용을 입력받아 LLM이 장애 보고서 초안을 구조화된 JSON 형태로 생성하는 FastAPI 기반 AI 서비스입니다.

운영 장애가 발생하면 개발자나 운영 담당자는 로그, 알림 메시지, 대응 메모, 고객 문의 등을 바탕으로 장애 상황을 빠르게 정리해야 합니다.

하지만 실제 장애 상황에서는 정보가 여러 곳에 흩어져 있고, 보고서 작성 품질도 담당자마다 달라질 수 있습니다.

이 프로젝트는 LLM을 활용해 장애 내용을 일정한 형식으로 정리하고, 원인 후보와 추가 확인 필요 항목을 분리하여 장애 보고서 초안 작성 시간을 줄이는 것을 목표로 합니다.

---

## 2. 해결하려는 문제

운영 장애 대응 과정에서는 다음과 같은 문제가 자주 발생합니다.

### 2.1 장애 내용 정리에 시간이 오래 걸림

장애 발생 시 로그, 알림, 대응 메모, 고객 문의 등을 사람이 직접 읽고 정리해야 합니다.

특히 장애 직후에는 빠른 공유가 필요한데, 보고서 작성 자체가 추가 업무 부담이 됩니다.

### 2.2 보고서 품질이 작성자에 따라 달라짐

같은 장애라도 작성자에 따라 다음 항목이 누락될 수 있습니다.

- 장애 요약
- 사용자 영향 범위
- 원인 후보
- 수행한 조치
- 추가 권장 조치
- 추가 확인 필요 항목

### 2.3 AI가 원인을 단정하면 위험함

장애 분석에서 원인은 확정된 사실과 후보를 구분해야 합니다.

LLM이 입력 내용을 바탕으로 원인을 성급하게 단정하면 잘못된 장애 보고서가 생성될 수 있습니다.

따라서 이 프로젝트에서는 원인을 `suspected_causes`로 분리하고, 확실하지 않은 내용은 `needs_confirmation`에 넣도록 설계했습니다.

## 3. 주요 기능

현재 v1에서 제공하는 기능은 다음과 같습니다.

### 3.1 장애 보고서 자동 요약

장애 제목과 상세 내용을 입력하면 LLM이 다음 항목으로 구조화합니다.

- 장애 요약
- 장애 영향 범위
- 가능성 있는 원인 후보
- 이미 수행한 조치
- 추가 권장 조치
- 장애 심각도
- 추가 확인 필요 항목

### 3.2 JSON Structured Output

LLM 응답을 자유로운 문장이 아니라 정해진 JSON 구조로 반환합니다.

```json
{
  "summary": "장애 요약",
  "impact": "장애 영향 범위",
  "suspected_causes": ["가능성 있는 원인 후보"],
  "completed_actions": ["이미 수행한 조치"],
  "recommended_actions": ["추가 권장 조치"],
  "severity": "LOW | MEDIUM | HIGH | CRITICAL",
  "needs_confirmation": ["추가 확인 필요 항목"]
}
